# .gitignore

在深入细节之前，先做一个概要说明：在 `ggml` 目录下的 `.gitignore` 文件列出了两个 Vulkan 着色器相关的生成文件（`src/ggml-vulkan-shaders.hpp` 和 `src/ggml-vulkan-shaders.cpp`），它们并不出现在源码库中，因为它们会在构建阶段由 CMake 和一个专门的工具（`vulkan-shaders-gen`）自动生成；这样可以避免将临时或二进制数据提交到仓库中。实际的着色器逻辑源码是若干 `.comp` 文件，这些文件在编译时被 `glslc` 编译成 SPIR‑V 二进制，并由 `vulkan-shaders-gen` 转换成 C++ 数组，最终写入上述被忽略的头文件和源文件中。

 - .gitignore文件是git工具的配置文件，该配置文件将会被git工具读取使用从而影响git工具的行为。git工具将会逐行读取配置文件中罗列出来的规则。
 - .gitignore文件作用就是为了让git工具知道哪些文件需要被追踪处理哪些文件是不需要被追踪处理的。
 - (*.comp)---(CMake + vulkan-shaders-gen)--->(.cpp + .hpp)

---

## 1. 为什么要在 `ggml/.gitignore` 中忽略这两个文件？
- **生成文件不应纳入版本控制**
  在源码目录下，**`src/ggml-vulkan-shaders.hpp`** 和 **`src/ggml-vulkan-shaders.cpp`** 都是由构建系统自动生成的中间产物，因此不应该纳入 Git 提交，以防止二进制或临时文件污染仓库历史，也避免因生成方式变化而引发的无意义差异[^1].
- **防止 in‑source 构建污染**
  如果用户在源码树（in‑source）中直接运行 `cmake` 并构建，生成文件会被写到源码子目录下，`.gitignore` 能确保这些文件不出现在 `git status` 中；而大多数用户推荐的 out‑of‑source 构建则会把它们放到单独的 `build/` 目录，从而完全不会影响源码[^2].

---

## 2. `src/ggml-vulkan-shaders.hpp` 与 `src/ggml-vulkan-shaders.cpp` 是什么？

### 2.1 输入：`.comp` 着色器源码
在 `ggml/src/ggml-vulkan/vulkan-shaders/` 目录中存在大量以 `.comp` 为后缀的文件（如 `add.comp`、`mul.comp`、`group_norm.comp` 等），它们是用 **GLSL**（OpenGL Shading Language）编写的计算着色器，用于在 GPU 上执行矩阵乘法、量化、归一化等张量运算[^3][^6].

### 2.2 生成工具：`vulkan-shaders-gen`
CMakeLists 中通过 `add_custom_command` 调用了一个名为 **`vulkan-shaders-gen`** 的二进制程序，该程序会：
1. 调用系统的 **`glslc`**（Khronos 提供的 GLSL 到 SPIR‑V 编译器）将每个 `.comp` 文件编译成 SPIR‑V 二进制码[^2].
2. 读取生成的 SPIR‑V 二进制文件（SPIR‑V 是 Vulkan 的标准中间表示格式[^4][^5]），并将其内容以 `uint8_t` 数组形式写入到一个 C++ 头文件和一个源文件中，从而在运行时可以直接将这些数组传递给 Vulkan API 创建 `VkShaderModule`[^9].

### 2.3 输出：头文件与源文件
- **`ggml-vulkan-shaders.hpp`**
  声明了所有着色器对应的外部数组和长度变量，例如：
  ```cpp
  extern unsigned char add_f32_data[1234];
  const uint64_t add_f32_len = 1234;
  ```
- **`ggml-vulkan-shaders.cpp`**
  定义了上述数组，对每个字节以十六进制字面量形式初始化，例如：
  ```cpp
  unsigned char add_f32_data[1234] = {
    0x03, 0x02, 0x23, /* … 省略 … */
  };
  ```
这些文件在编译时被 `target_sources(ggml-vulkan PRIVATE …)` 添加到 Vulkan 后端的目标中，以便链接进最终的库或可执行文件[^2].

---

通过上述机制，`llama.cpp` 将所有 GPU 计算的核心逻辑嵌入到单一的 C++ 库中，无需在运行时依赖外部文件系统读取着色器；同时借助 `.gitignore` 保持源码仓库整洁。

# vulkan着色器

## 概要
在 `ggml` 目录下，`src/ggml-vulkan-shaders.hpp` 和 `src/ggml-vulkan-shaders.cpp` 确实是“随需生成”的，它们不会放在源码库中，而是在构建过程中通过 CMake 自动生成，并立即被加入到 `ggml-vulkan` 后端库的编译流程中。生成流程分三步：
1. **准备工具链**：借助 `find_package(Vulkan COMPONENTS glslc REQUIRED)` 定位 `glslc` 编译器[^1]。
2. **构建生成器**：通过 `ExternalProject_Add` 编译一个名为 `vulkan-shaders-gen` 的辅助工具，将其产物放入二进制目录[^10].
3. **执行自定义命令**：`add_custom_command` 调用该生成器，遍历所有 `.comp` GLSL 着色器源码，先用 `glslc` 转为 SPIR‑V，然后把 SPIR‑V 二进制转成 C++ 数组写入上面两个目标文件，并立刻作为源文件加入后端编译[^2].

---

## 1. 生成后是否会被使用？
- **是的**，在同一份 CMake 配置里，生成命令声明了这两个文件为输出（`OUTPUT …/ggml-vulkan-shaders.hpp` 与 `…/ggml-vulkan-shaders.cpp`），随后通过
  ```cmake
  target_sources(ggml-vulkan PRIVATE
    ${_ggml_vk_source}
    ${_ggml_vk_header}
  )
  ```
  将它们加入到 `ggml-vulkan` 库的编译列表中，保证它们被编译并链接进最终产物[^2].
- 因此，无论是单纯的 in‑source 构建还是推荐的 out‑of‑source 构建，这两个文件都会按需生成并使用。

---

## 2. 自动生成的详细流程

### 2.1 定位 `glslc` 工具
CMake 首先执行：
```cmake
find_package(Vulkan COMPONENTS glslc REQUIRED)
```
这一步会查找 Vulkan SDK 中的 `glslc` 命令，用于将 GLSL 源码编译为 SPIR‑V 二进制[^1][^9].

### 2.2 构建 `vulkan-shaders-gen`
若非交叉编译，CMake 会进入：
```cmake
add_subdirectory(vulkan-shaders)               # 此处包含生成器源码
```
并通过
```cmake
ExternalProject_Add(
  vulkan-shaders-gen
  SOURCE_DIR  ${CMAKE_CURRENT_SOURCE_DIR}/vulkan-shaders
  CMAKE_ARGS  -DCMAKE_TOOLCHAIN_FILE=${HOST_CMAKE_TOOLCHAIN_FILE}
              -D…  # 多个扩展检测选项
  BUILD_COMMAND   ${CMAKE_COMMAND} --build .
  INSTALL_COMMAND ${CMAKE_COMMAND} --install .
  INSTALL_DIR     ${CMAKE_BINARY_DIR}
)
```
编译出 `vulkan-shaders-gen` 可执行文件，放在 `${CMAKE_RUNTIME_OUTPUT_DIRECTORY}` 目录下[^10][^4].

### 2.3 运行自定义命令生成头/源文件
随后，CMake 收集：
```cmake
file(GLOB _ggml_vk_shader_deps "${_ggml_vk_input_dir}/*.comp")
set (_ggml_vk_shader_deps
  ${_ggml_vk_shader_deps}
  vulkan-shaders-gen
  vulkan-shaders-gen-build
  vulkan-shaders-gen-install
)
add_custom_command(
  OUTPUT ${_ggml_vk_header} ${_ggml_vk_source}
  COMMAND ${_ggml_vk_genshaders_cmd}
    --glslc      ${Vulkan_GLSLC_EXECUTABLE}
    --input-dir  ${_ggml_vk_input_dir}
    --output-dir ${_ggml_vk_output_dir}
    --target-hpp ${_ggml_vk_header}
    --target-cpp ${_ggml_vk_source}
    --no-clean
  DEPENDS ${_ggml_vk_shader_deps}
  COMMENT "Generate vulkan shaders"
)
```
此命令会：
1. 遍历 `vulkan-shaders/` 目录下所有 `.comp` 文件（Glsl 计算着色器）[^3][^8].
2. 对每个文件调用 `${Vulkan_GLSLC_EXECUTABLE}`（即 `glslc`）编译为 SPIR‑V 二进制[^1][^7].
3. 将 SPIR‑V 二进制读入并按字节生成 `unsigned char data[]` 数组，输出到目标头文件和源文件中[^5].

### 2.4 着色器嵌入 C++
生成的 `ggml-vulkan-shaders.hpp` 会声明各着色器的外部数据数组和长度，如：
```cpp
extern unsigned char add_f32_data[1234];
const uint64_t add_f32_len = 1234;
```
而 `ggml-vulkan-shaders.cpp` 则以十六进制字面量初始化数组，方便在运行时直接通过 Vulkan API 创建 `VkShaderModule`[^5][^6].

---

通过上述一步步配置，`llama.cpp` 将所有 Vulkan 计算着色器静态嵌入到库中，无需运行时从文件系统加载，同时通过 `.gitignore` 保持源码树整洁，避免提交由生成器产生的中间文件。
